# Implementation Plan

> **実行モードに関する注記**: 全タスクは単一ファイル `design/pencil-new.pen` を単一の Pencil MCP セッションで編集するため、共有可変リソースの競合により並列実行できない。よって `(P)` マーカーは付与せず、記載順の sequential で実行する。
>
> **Pencil 描画不具合時の対応（フォールバック禁止）**: タスクの検証で全景スクショが黒化／白化した場合、葉ノード個別スクショで「データは正常」と判断して**先に進めてはならない**。これは Pencil が正しく描画できていない状態であり、ユーザーのエディタ側でも崩れている可能性がある。**全景スクショが正常に描画されるまで、ユーザーに Pencil（MCP 接続）の再接続を依頼して待つ**。正常描画を確認できてから検証・完了判定を行う（research.md 参照）。
>
> **セルフレビュー・ゲート（全ペンシル生成タスク共通・必須）**: 画面・コンポーネントを新規作成または変更した各タスクは、`- [x]` を付ける**前に必ず**全景スクショを撮り、以下を**甘くなく**自己批評して通過させること。ユーザーに指摘させてからの手戻りを前提にしない。未通過なら完了とせず、その場で当該ノードを直接修正してから再レビューする。
> 1. **脱・箱**: 見出し＋内容の塊を囲み枠カードに入れていないか（入力欄・比較画像・データ表など「独立オブジェクト／機能的コントロール」のみ枠を許容）。同じ視覚的重みの箱を並べていないか。
> 2. **hero 1つ**: 1 画面に主役が1つ立っているか。発光する人格が主役になるべき画面で脇役になっていないか。
> 3. **発光は人格のみ**: glow が人格要素だけに付き、檻側（ブランド・チップ・ボタン・パネル）に付いていないか（blur≤12・低 alpha）。
> 4. **トークン**: spacing/type が 4/8 グリッド（`space-*`/`text-*`）にスナップ、数値・ID・スコアが Mono、ペルソナ識別が family 色か。配色は無彩3階層＋単一アクセント＋セマンティック少数か。
> 5. **整合**: レイアウト崩れ・クリップ・はみ出し・死に余白がないか（`snapshot_layout` 併用）。情報設計が現行 React アプリの正と一致しているか。

  - レーダーの**凡例（A案/B案）は見出しの直下に左寄せ**で置き（見出し行ではない）、チャート直下中央にも置かない
  - 各塊は紙面（bg-base）直置き・余白・hairline・タイポ階層で領域化し、独立オブジェクト（レーダー／比較画像／データ表）のみ枠を許容する。hero は1つに絞り、箱の積み上げにしない

### (e) 既知の注意点
- **Pencil は単一ファイル・単一セッションで並列編集不可**。`design/pencil-new.pen` は1セッションで sequential に編集する。
- **ただし `.md` 文書の更新はサブエージェントで並列可**（.pen を触らない作業に限る）。
- **新規作成した入れ子ダークフレームは描画追従が遅れ、黒化/白化する場合がある**。`batch_get` でデータが正常なことを確認しつつ、再描画後に完了判定すること。
- **フォールバック禁止**: 全景スクショが黒化/白化したとき、葉ノード個別スクショで「データは正常」と判断して先に進めてはならない。全景スクショが正常描画されるまでユーザーに Pencil（MCP 接続）の再接続を依頼して待ち、正常確認後に検証・完了判定する。
- **セルフレビュー・ゲート必須**: 画面・コンポーネントの新規作成/変更タスクは `- [x]` を付ける前に必ず全景スクショを撮り、脱・箱／hero1つ／発光は人格のみ／トークン／整合を甘くなく自己批評して通過させること（ユーザーの指摘を前提にしない）。
